# Patterns

The one way this template does each thing, layer by layer. [AGENTS.md](../AGENTS.md) holds the rules; this file
shows them applied, using the `note` module as the worked example. Reasons live in [DECISIONS.md](DECISIONS.md).

When you implement a task:

1. Read the section for every layer you touch before writing code.
2. Copy the shape shown here. If the task needs something no section covers, pick the simplest option consistent
   with these patterns and add a line to `docs/DECISIONS.md`.
3. Finish with the [checklist](#checklist-for-a-new-endpoint).

## Project structure

```text
cmd/server/                 one binary: serve (default), worker, migrate
internal/
  app/                      config + validation table, wiring, middleware, routes, worker, adapters for ports
  module/<name>/            one feature boundary per package
  platform/<pkg>/           shared plumbing: database, httpx, scope, listquery, apierr, clock, testkit, cleanup
migrations/                 goose SQL, embedded in the binary
config/config.yaml          defaults, ${ENV_VAR:default}
api/swagger/                generated by make swagger, committed
deploy/                     compose, helm, bootstrap SQL
```

Import direction is enforced by `internal/app/arch_test.go`:

| Package | May import | Must not import |
|---|---|---|
| `internal/app` | anything | — |
| `internal/module/<a>` | `platform/*`, its own subpackages, go-sdk | `internal/app`, `internal/module/<b>` |
| `internal/platform/*` | other `platform/*`, go-sdk | `internal/app`, any module |

Inside a module, calls go `handler → service → repository`, never back up. `internal/` holds only `app`, `module`
and `platform`; a new top-level folder under `internal/` is not allowed.

## Module anatomy

One package per feature, one file per role:

| File | Holds |
|---|---|
| `module.go` | Permission constants, `Deps`, `Module`, `New`, `Register` |
| `config.go` | The `modules.<name>` config block and its `Validate` |
| `model.go` | Package doc comment, row structs, write inputs (`NewX`, `Patch`), enums, scope types |
| `dto.go` | Request and response DTOs, `newXResponse` mappers |
| `handler.go` | HTTP: routes, decode, validate, call the service, map to DTO, swag annotations |
| `service.go` | Business rules and permission widening; no HTTP types |
| `repository.go` | The `Repository` interface and its SQL implementation |
| `*_test.go` | Handler/service tests over a mocked repository |
| `*_integration_test.go` | Repository and list tests against real Postgres |

`module.go` is the only thing `internal/app` touches:

```go
const (
    PermRead     = "notes:read"      // the caller's own
    PermReadAny  = "notes:read:any"  // the whole tenant
    PermWrite    = "notes:write"
    PermWriteAny = "notes:write:any"
)

// Deps are what note needs from internal/app. List only what the module uses.
type Deps struct {
    DB    *sqlkit.DB
    V     validator.Validator
    Authz authz.Authorizer
}

func New(cfg Config, deps Deps) *Module {
    svc := NewService(cfg, NewRepository(deps.DB), deps.Authz)
    return &Module{h: NewHandler(svc, deps.V, deps.Authz)}
}

func (m *Module) Register(rt *httpx.Routes) {
    rt.API.Route("/notes", m.h.Register)
}
```

- Permission keys are `<resource>:<action>` with an optional `:any` that widens from owner to tenant. Every key is
  registered in identity's `modules.rbac.permissions`.
- Pick the route group by audience: `rt.API` (`/v1`, authenticated), `rt.Me` (`/v1/me`, the caller is the target),
  `rt.Admin` (`/v1/admin`, every route adds `RequirePermission`), `rt.Internal` (`/v1/internal`, service tokens),
  `rt.Root` (outside `/v1`). Modules never create a group.
- Wire the module with one entry in `buildModules` (`internal/app/module.go`). The README's "Add a module" section is
  the step-by-step.
- A helper used by one module only is a subpackage of that module (`internal/module/note/<helper>`), never a
  `platform` package.

## Config

A block is a struct with `mapstructure` tags and a `Validate` method, plus one row in `Config.sections()` in
`internal/app/config.go`:

```go
type Config struct {
    ListMaxSize int `mapstructure:"list_max_size"`
}

func (c Config) Validate() error {
    if c.ListMaxSize < 1 || c.ListMaxSize > maxListSize {
        return errorz.BadRequest().WithMessage("list_max_size must be between 1 and 100")
    }
    return nil
}
```

```go
{"modules.note", c.Modules.Note.Validate},
```

Startup runs every row and names the failing one (`error: config modules.note: list_max_size must be …`).
Per-environment values go in `config/config.yaml` as `${ENV_VAR:default}`, and every new variable gets a line in
`.env.example`. Secrets are never defaults in `config.yaml`.

## Models and DTOs

Three kinds of struct, never mixed:

| Kind | File | Example | Rule |
|---|---|---|---|
| Row | `model.go` | `Note` | Mirrors the table. Never serialised to a response, log or cache key |
| Write input | `model.go` | `NewNote`, `Patch` | What the service accepts. `Patch` fields are pointers: nil means untouched |
| DTO | `dto.go` | `CreateNoteRequest`, `NoteResponse` | `json` and `validate` tags. Only fields the client may send or see |

```go
type UpdateNoteRequest struct {
    Title  *string `json:"title" validate:"omitnil,min=1,max=200"`
    Status *string `json:"status" validate:"omitnil,oneof=draft archived"`
}

func newNoteResponse(n *Note) *NoteResponse {
    return &NoteResponse{ID: n.ID.String(), Title: n.Title, Version: n.Version, UpdatedAt: n.UpdatedAt.UTC() /* … */}
}
```

- `tenant_id`, `owner_id` and `created_by` are never request fields: they come from the token. The strict decoder
  turns a body naming them into a 400.
- Response IDs are strings, times are UTC, and editable resources return `version`.
- Enum values are typed constants in `model.go` (`StatusDraft`) and mirrored by a `CHECK` in the migration.
- List responses are `dto.PageResponse[XResponse]` aliased as `XPageResponse`.

## Handlers

A handler is a `func(*http.Request) (any, error)` wrapped by `httpx.Handle`, which writes the status and envelope.
Never call `w.WriteHeader` or encode JSON by hand.

```go
func (h *Handler) Register(r chi.Router) {
    read := middleware.RequireAny(h.az, PermRead, PermReadAny)
    write := middleware.RequirePermission(h.az, PermWrite)
    r.With(write).Post("/", httpx.Handle(h.create))
    r.With(read).Get("/", httpx.Handle(h.list))
    r.With(read).Get("/{id}", httpx.Handle(h.get))
    r.With(write).Patch("/{id}", httpx.Handle(h.update))
    r.With(write).Delete("/{id}", httpx.Handle(h.delete))
}

func (h *Handler) update(r *http.Request) (any, error) {
    id, err := noteID(r)                 // malformed UUID → 404
    if err != nil {
        return nil, err
    }
    version, err := httpx.Version(r, nil) // If-Match: missing → 428, malformed → 400
    if err != nil {
        return nil, err
    }
    var in UpdateNoteRequest
    if err := httpx.DecodeJSON(r, &in); err != nil { // unknown field, bad type, >1 MiB → 400
        return nil, err
    }
    if err := h.v.ValidateStruct(&in); err != nil {
        return nil, err
    }
    if in == (UpdateNoteRequest{}) {
        return nil, errorz.BadRequest().WithMessage("body must set at least one field")
    }
    n, err := h.svc.Update(r.Context(), id, version, &Patch{Title: in.Title, Status: in.Status})
    if err != nil {
        return nil, err
    }
    return newNoteResponse(n), nil
}
```

| Outcome | Return |
|---|---|
| 200 with data | the DTO |
| 201 | `&response.Success{HTTPStatusCode: http.StatusCreated, Data: dto}` |
| 204 | `&response.Success{HTTPStatusCode: http.StatusNoContent}` |
| Any error | the `error`; `errorz` code picks the status |

- Order is always: path params → `If-Match` → decode → validate → service → map to DTO.
- Path params come from `chi.URLParam`. A path ID that is not a UUID is a 404, not a 400: it names no resource.
- Permissions are route middleware. The handler never checks a permission itself; `:any` widening is the service's.
- The handler maps DTO → write input and row → DTO. It never passes a DTO to the service.
- Every handler has swag annotations: `@Summary`, `@Description` (name the permission), `@Tags`, `@Param` for every
  path, header, body and query key, `@Security BearerAuth`, `@Success`, every `@Failure` it can return, `@Router`.
  Run `make swagger` and commit `api/swagger/`.

## Validation

Each check lives in exactly one layer:

| Layer | Checks | Error |
|---|---|---|
| `httpx.DecodeJSON` | JSON shape, unknown fields, types, body size | 400, `meta.fields` names the field |
| Handler, `validate` tags | Required, length, `oneof`, format of the request alone | 400, `meta.fields` with `json` names |
| Handler, code | Cross-field rules on the request (`PATCH` sets at least one field) | 400 |
| Service | Rules that need state, config or permissions (`owner_id` filter needs `:any`, range order) | 400 / 403 |
| Database | `NOT NULL`, `CHECK`, unique and foreign keys: the last line for any path that skips the service | 409 / 500 |

- The validator uses `json` field names (`validator.field_name_tag: json`), so `meta.fields` keys match the body.
- The service trusts typed inputs from the handler and does not repeat tag validation. It does re-check list
  parameters (see [List endpoints](#list-endpoints)) because a second caller could skip the handler.
- A 400 about one field uses `meta.fields`:

```go
func badQuery(field, msg string) error {
    return errorz.BadRequest().WithMessage(field+": "+msg).WithMeta(apierr.MetaFields, map[string]string{field: msg})
}
```

- A unique violation the client can cause (a duplicate name) is caught in the repository and returned as
  `errorz.Conflict()`, not left as a 500.

## Errors

- Functions return `error`, never `*errorz.Error` (a typed nil is a non-nil `error`).
- Build errors from `errorz` constructors: `BadRequest`, `NotFound`, `Forbidden`, `Conflict`,
  `PreconditionRequired`, `Internal`. The code selects the HTTP status. Never invent a code: unknown maps to 500.
- Wrap infrastructure failures with a code and a `<module>: <step>` message:

```go
return errorz.Wrap(err).WithCode(errorz.CodeInternal).WithMessage("note: list")
```

- A reason clients branch on goes in `meta.reason` through `apierr.New(apierr.ReasonX)`. Add the reason and its
  code to `internal/platform/apierr/reasons.go`; the map keeps a reason from pairing with the wrong status.
- Compare with `errors.Is(err, errorz.ErrNotFound)`, never by message.
- Out of scope is 404, never 403: another tenant's or user's ID must be indistinguishable from a missing one. 403 is
  only for "you lack this permission" on something you are allowed to know exists.
- Each module has one `errNotFound()` so every miss reads the same.

## Services

The service holds business rules and decides how far the caller reaches. It knows nothing about HTTP.

```go
type Service struct {
    repo      Repository
    az        authz.Authorizer
    listQuery listquery.ListParseConfig
}

func (s *Service) Update(ctx context.Context, id uuid.UUID, version int, p *Patch) (*Note, error) {
    return s.repo.Update(ctx, id, version, p, s.owners(ctx, PermWriteAny))
}

// owners widens a call to every owner when the caller holds anyPerm.
func (s *Service) owners(ctx context.Context, anyPerm string) Owners {
    if s.az.Can(ctx, anyPerm) {
        return AnyOwner
    }
    return OwnNotes
}
```

- `Service` is a concrete struct. It depends on interfaces it consumes (`Repository`, ports) so tests can fake them.
- `ctx` is the first parameter. The tenant and caller are read from `ctx` downstream, never passed as arguments.
- The service passes a typed scope (`OwnNotes` / `AnyOwner`) to the repository. It never builds a tenant filter.
- Time comes from a `clock.Clock` field, never `time.Now()`, whenever the rule depends on it (expiry, windows).
- Several writes that must succeed together run in `database.WithTx` here, not in the repository.
- Thin pass-through methods are fine; do not add logic to make the layer look busy.

## Repositories

### Interface and implementation

The module declares `Repository` as an interface (with a `//go:generate mockgen` line) and returns the SQL
implementation from `NewRepository(db)`. Each method is an intent: `Create`, `Get`, `List`, `Update`, `Delete`,
`SetStatus`, never a generic `Save(entity)`.

```go
//go:generate go run go.uber.org/mock/mockgen@v0.6.0 -source=repository.go -destination=mock_repository_test.go -package=note

type Repository interface {
    Create(ctx context.Context, n *NewNote) (*Note, error)
    Get(ctx context.Context, id uuid.UUID, owners Owners) (*Note, error)
    List(ctx context.Context, opts *repository.ListOptions, search string, owners Owners) ([]Note, int64, error)
    Update(ctx context.Context, id uuid.UUID, version int, p *Patch, owners Owners) (*Note, error)
    Delete(ctx context.Context, id uuid.UUID, owners Owners) error
}

func NewRepository(db *sqlkit.DB) Repository {
    return &sqlRepository{base: reposql.NewBaseRepository(db, "note")}
}
```

The repository returns errors and never logs.

### Scope comes from the context

The repository reads the tenant and owner itself with `scope.Tenant(ctx)` / `scope.Owner(ctx)`. A missing tenant is
a 401, so a forgotten filter fails loudly instead of leaking rows. Every statement filters on `tenant_id`, plus
`owner_id` when scoped to the owner:

```go
const scopeWhere = ` WHERE id = $1 AND tenant_id = $2 AND ($3::uuid IS NULL OR owner_id = $3)`
```

`tenant_id` is never a parameter of a repository method and never a client-supplied filter.

### Leader or follower

| Query | Connection |
|---|---|
| Writes, locks, transactions | `r.base.GetConnection(ctx)` or `database.Leader(ctx, db)` (joins the ctx transaction) |
| A read right after a write, or a read that decides a write (`Get` used by `Update`) | Leader, as above |
| Lists, search, reports | `r.base.GetReadConnection(ctx)` or `db.Follower()` (falls back to the leader) |

### Named columns, one select list, one scanner

```go
const noteColumns = `id, tenant_id, owner_id, title, body, status, pinned, version, created_at, updated_at, created_by`

func scanNote(row interface{ Scan(dest ...any) error }) (*Note, error) {
    var n Note
    err := row.Scan(&n.ID, &n.TenantID /* … same order as noteColumns */)
    if errors.Is(err, sql.ErrNoRows) {
        return nil, errNotFound()
    }
    if err != nil {
        return nil, errorz.Wrap(err).WithCode(errorz.CodeInternal).WithMessage("note: scan")
    }
    return &n, nil
}
```

- Inserts and updates use `RETURNING <columns>` so the caller gets the stored row in one round trip.
- Never `SELECT *`. Never string-concatenate a value into SQL: values are `$n` placeholders; only column names from
  an allow-list are ever concatenated.

### Updates write only their own columns

Intent methods update only the columns they own. A `Patch` builds `SET` from its non-nil fields:

```go
sets := []string{"version = version + 1", "updated_at = now()"}
set := func(column string, v any) {
    args = append(args, v)
    sets = append(sets, fmt.Sprintf("%s = $%d", column, len(args)))
}
if p.Title != nil {
    set("title", *p.Title)
}
```

A field the caller never loaded is never overwritten.

### Optimistic locking

Editable tables carry `version int NOT NULL DEFAULT 1`. An update checks and bumps it. When no row matches, look
again to tell the two cases apart:

```go
row := conn.QueryRowContext(ctx, `UPDATE note SET `+sets+scopeWhere+` AND version = $4 RETURNING `+noteColumns, args...)
n, err := scanNote(row)
if !errors.Is(err, errorz.ErrNotFound) {
    return n, err
}
if _, err := r.Get(ctx, id, owners); err != nil {
    return nil, err // out of scope or gone: 404
}
return nil, apierr.New(apierr.ReasonVersionConflict) // in scope, other version: 409
```

The client sends the version in `If-Match`; the response returns the new one.

### Delete

Zero rows affected is a 404:

```go
res, err := conn.ExecContext(ctx, `DELETE FROM note`+scopeWhere, id, tenant, owner)
// …
if n, _ := res.RowsAffected(); n == 0 {
    return errNotFound()
}
```

Soft delete is opt-in per table: `UPDATE … SET deleted_at = now() WHERE … AND deleted_at IS NULL`, every read adds
`deleted_at IS NULL`, and unique constraints become partial indexes
(`CREATE UNIQUE INDEX … (tenant_id, title) WHERE deleted_at IS NULL`).

### Secrets in their own tables

Password hashes, token hashes and API keys live in a separate table, read by a struct that is never serialised into
a response, a log line or the cache.

## Transactions and locks

| Helper | Use |
|---|---|
| `database.WithTx(ctx, db, fn)` | A service step whose writes must commit together. Refuses to nest |
| `database.InTx(ctx, db, fn)` | A step that must be atomic but may already run inside a transaction (bootstrap) |
| `database.LockXact(ctx, key)` | Serialise a critical section across pods; only inside a transaction |

```go
err := database.WithTx(ctx, s.db, func(ctx context.Context) error {
    n, err := s.notes.Create(ctx, in)
    if err != nil {
        return err
    }
    return s.outbox.Enqueue(ctx, "note.created", n.ID.String(), event)
})
```

- Repositories join the transaction automatically through `ctx` (`GetConnection` / `database.Leader`). Always pass
  the `ctx` that `fn` receives, not the outer one.
- Returning an error from `fn` rolls everything back. Do not call anything that leaves the service (HTTP, email,
  queue) inside `fn`; enqueue it in the outbox instead.
- Keep transactions short: no waiting on other services inside one.

## Side effects: the outbox

Anything that leaves the service (email, queue message, webhook) is written with `Outbox.Enqueue` in the same
transaction as the change. The worker's dispatcher sends it later.

1. Enqueue in the service, inside `WithTx`, with a topic (`<module>.<event>`) and a key (usually the aggregate ID).
2. Register a `database.Sender` for the topic in `senders()` in `internal/app/worker.go`.
3. The sender must tolerate duplicates: a crash between sending and recording the send resends.
4. A payload may carry a top-level `expires_at` (RFC 3339); a row past it is never sent.

Failed sends retry with exponential backoff; the cleanup job deletes sent and expired rows.

## List endpoints

One `listquery.ListParseConfig` per list, built in the service:

```go
listquery.ListParseConfig{
    MaxSize:             cfg.ListMaxSize,
    AllowedSortFields:   []string{"title", "status", "pinned", "created_at", "updated_at"},
    AllowedFilterFields: []string{"title", "status", "pinned", "owner_id", "created_at"},
    FilterOperators: map[string][]repository.FilterOperator{ // a field left out takes eq and like
        "title":      {eq, ne, like},
        "created_at": {gt, gte, lt, lte, listquery.OperatorBetween},
        "status": {eq}, "pinned": {eq}, "owner_id": {eq},
    },
    AllowedParams: []string{"search", "created_from", "created_to"}, // endpoint-owned, parsed by the handler
}
```

- The handler parses (`listquery.ParseListParams`) for a fast 400; the service validates again
  (`listquery.ValidateListParams`, fields, operators and value shape) so no caller skips the allow-lists.
- Syntax: `field=value;operator` (`;` percent-encoded as `%3B`; no operator means `eq`), repeatable
  `sort=field,ASC|DESC`, `page`, `size`.
- Operators: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `like`, `in`, `between`, `is_null`, `is_not_null`.
  - `in`: `status=a,b;in`, each item percent-encoded by the client, at most 100.
  - `between`: `a,b`, inclusive; `ToListOptions` expands it to `gte a` and `lte b`.
  - `is_null`, `is_not_null`: the value is ignored, `archived_at=;is_null`.
  - `like` is case-sensitive contains; there is no `ilike` and no OR group.
- Give every filter field an explicit operator list; the eq-and-like default only keeps old configs working.
- The service type-checks each filter value against its column (`typeFilters`): a bad UUID, boolean or date is a
  400 naming the key, not a Postgres 500.
- A filter that widens scope (`owner_id`) needs the `:any` permission, checked in the service (403).
- Search and the legacy `created_from`/`created_to` range are endpoint-owned params (`ListExtra`), turned into
  conditions or SQL in the service and repository.
- The repository prepends the scope conditions, builds `WHERE` with `reposql.BuildWhereClause`, applies a default
  order when none is given and always appends `id` as the last sort key so pages are stable.
- Each query key gets an `@Param` line naming the operators it accepts.

## Options endpoints

Every resource a dropdown can pick from gets `GET /v1/<resource>/options`, behind the list's permission:

- Query: `search` (the list's search), `ids` (comma-separated, up to 100), `page`, `size` (default 20, max 50).
  Parse it with its own `ListParseConfig{MaxSize: 50, AllowedParams: []string{"search", "ids"}}` so unknown keys
  are 400s.
- Response: the usual `dto.PageResponse` of `{ "value": "<id>", "label": "<display name>" }`.
- Order by label, then id (the repository appends `id`), so infinite scroll is stable.
- `ids` returns exactly those rows, so a form can show labels for values already selected; `search` and paging
  are ignored. An id out of scope (another tenant, or another owner without `:any`) is left out silently.
- The same scope as the list: reuse the list's repository method with an `id IN (…)` condition. Never pass an
  empty `IN`: go-sdk drops it, which widens the query.
- Modules do not share a generic `/v1/options/{resource}` router, since modules must not import each other.

## Bulk actions

A bulk action is `POST /v1/<resource>/bulk-<action>`, behind the single-row permission. `note` has
`bulk-delete`:

- Body: exactly one of `{ "ids": [...] }` (1 to 100) or `{ "filter": "<list query string>" }`. Both, neither or
  an empty `ids` is a 400.
- `filter` is parsed with the list's own handler helper and `ListParseConfig`; `page`, `size` and `sort` are
  dropped. An empty `filter` means every row in scope. A raw `;` in it is accepted.
- The write scope applies (`:write:any` widens it; an `owner_id` filter needs it).
- One transaction: `DELETE … WHERE id IN (SELECT id … LIMIT cap+1 FOR UPDATE) RETURNING id`. More than the cap
  (1000) rolls back and returns 400 `TOO_MANY_ROWS`.
- No `If-Match`: bulk actions are last-write-wins.
- Response `200 { "affected": n, "failed": [{ "id": "…", "reason": "not_found" }] }`. A selected id that was not
  deleted, including one from another tenant, is `not_found`; a filter call has no `failed` rows.
- Not covered: bulk update, and async jobs for selections over the cap.

## Migrations

`make migrate-create name=<what>` writes `migrations/<UTC timestamp>_<what>.sql`.

```sql
-- +goose Up
CREATE TABLE note (
    id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id  uuid NOT NULL,
    owner_id   uuid NOT NULL,
    title      text NOT NULL,
    status     text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'archived')),
    version    int NOT NULL DEFAULT 1,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    created_by uuid NOT NULL
);
CREATE INDEX note_tenant_owner_updated ON note (tenant_id, owner_id, updated_at DESC);

-- +goose Down
DROP TABLE note;
```

- Base columns on every tenant-owned table: `id`, `tenant_id`, `owner_id` (if owner-scoped), `version` (if
  editable), `created_at`, `updated_at`, `created_by`.
- Every index starts with `tenant_id`.
- Every migration has a working `Down`.
- Expand then contract: a migration must work with the code already running. New columns are nullable or have a
  default; a rename is a new column plus backfill across two releases. Indexes on live tables use
  `CREATE INDEX CONCURRENTLY` in a `-- +goose NO TRANSACTION` file.
- Never edit a migration that has run anywhere; add a new one.

## Caching

No module caches today. Caching is off by default and opt-in per repository, and never for auth or secret tables
(stale reads are worse than a query for most resources). When a read is hot enough to need it:

- Cache in a decorator that implements the module's own `Repository` interface and wraps the SQL one, wired in
  `NewRepository` or `New`. Handlers and services do not know the cache exists.
- The key includes the tenant: `<module>:<tenant>:<id>`. A key without the tenant leaks rows across tenants. For
  that reason go-sdk's generic `repository/cache.CachedRepository`, which keys by ID only, does not fit
  tenant-scoped repositories.
- Read-through on `Get`; invalidate (delete the key) on every write to that row, after the transaction commits.
  Never write-behind.
- Cache only rows that are safe to show every caller allowed to reach them; re-check owner scope after a hit.
- A Redis error is a cache miss, never a failed request.
- Always set a TTL. Lists are not cached.
- Results of calls to other services (identity lookups) are cached in the adapter in `internal/app`, as the service
  token is.

## Calling another module or service

A module never imports another module. When it needs outside data (another module, identity's `/v1/internal`):

1. Declare a small interface (a port) in the consuming module, named for what it needs:

   ```go
   type UserDirectory interface {
       DisplayName(ctx context.Context, userID uuid.UUID) (string, error)
   }
   ```

2. Add it to the module's `Deps`.
3. Implement it in `internal/app` (calling the other module's service or identity's API) and wire it in
   `buildModules`.
4. The module's tests use a fake.

The README's "Call identity's internal API" section has the full example.

## Testing

| Kind | File | What it covers |
|---|---|---|
| Handler + service | `handler_test.go`, `*_test.go` | HTTP status, envelope, validation, permissions, over `MockRepository` |
| Repository | `repository_integration_test.go` | SQL, scope isolation, versions, against `testkit.Postgres(t)` |
| List | `list_integration_test.go` | Filters, sort, paging against seeded rows |
| Architecture | `internal/app/arch_test.go` | Import rules |

- Table-driven tests. Unit tests run under `go test -short`; integration tests skip under `testing.Short()` and live
  in `*_integration_test.go` (package `<name>_test`).
- Handler tests build the real service over the mock and a real `authz` with `SourceConfig` roles, and put claims in
  the context the way the auth middleware does.
- Every repository gets the isolation tests: another user in the same tenant and the same user in another tenant
  both get 404 on `Get`, `Update` (not 409, which would leak existence), `Delete` and an empty `List`.
- Regenerate mocks with `go generate ./internal/module/<name>` after changing the interface.
- Time-dependent code takes `clock.Clock`; tests use `testkit.NewClock`.

## Logging and secrets

- Never log secrets, tokens, passwords, or request and response bodies.
- Repositories and services return errors; the HTTP layer and the worker log them.
- Log with context (`ErrorWithContext`) and structured fields (`logger.F("outbox_id", id)`).

## Tracing

Tracing is go-sdk `tracer` (OpenTelemetry, OTLP/gRPC to Tempo), switched on by `tracing.enabled`. When it is off,
`internal/app` builds `tracer.NewNoOp()`, so code always calls the tracer and never checks whether it is on.

| Piece | State |
|---|---|
| Server span per request, W3C `traceparent` read from the request (`middleware.Tracing`) | Exists |
| `trace_id` on every request log line (`ctxkit.WithTraceID`), Grafana links logs ↔ traces | Exists |
| `X-Trace-Id` on every response and `trace_id` in the envelope; CORS exposes the header | Exists |
| Request spans named by chi route pattern (`GET /v1/notes/{id}`) | Exists |
| Tracer in module `Deps`, spans on service operations | To build |
| `tracing.End` helper in `internal/platform/tracing` | To build |
| Client spans and `traceparent` on outbound HTTP to identity (`identityClient`, go-sdk `tracer.Transport`) | Exists |
| Worker spans (outbox dispatch, cleanup) and `trace_id` on worker logs | To build |
| Database spans, one per statement (go-sdk `tracesql` around the pgx driver) | Exists |

### Where spans go

One span per unit of work a person would look for in a trace, not one per function:

| Span | Started in | Kind | Name |
|---|---|---|---|
| Incoming request | `middleware.Tracing` (done for you) | server | `GET /v1/notes/{id}` |
| Service operation (a use case) | the service method | internal | `note.Update` |
| Call to another service | the adapter or client in `internal/app` | client | `identity GET /v1/internal/users/{id}` |
| Worker job run | the job's loop | internal (root) | `outbox.dispatch`, `cleanup.run` |
| One outbox send | the dispatcher, per message | producer | `outbox.send note.created` |

Handlers and repositories do not start spans: the request span covers the handler, and the service span covers
its repository calls. A repository method gets its own span only when it runs several statements whose timing
matters on its own (a long report).

### The service span

The tracer comes in through `Deps` and the `Service` struct, never a global:

```go
type Deps struct {
    DB     *sqlkit.DB
    V      validator.Validator
    Authz  authz.Authorizer
    Tracer tracer.Tracer
}

func (s *Service) Update(ctx context.Context, id uuid.UUID, version int, p *Patch) (_ *Note, err error) {
    ctx, span := s.tr.Start(ctx, "note.Update", tracer.WithAttributes(map[string]any{"note.id": id.String()}))
    defer func() { tracing.End(span, err) }()

    return s.repo.Update(ctx, id, version, p, s.owners(ctx, PermWriteAny))
}
```

- Always continue with the `ctx` that `Start` returns, so repository calls, transactions and outbound calls become
  children of the span.
- Use a named `err` result and the deferred `tracing.End`, so every return path ends the span and records the
  outcome.
- Thin pass-through methods (`Get`, `Delete` that only call the repository) may skip the span; the request span
  already times them. Add one as soon as the method does more than one call.
- A transaction runs inside the service span: `WithTx(ctx, …)` gets the span's `ctx`.

### Errors on spans

`tracing.End(span, err)` marks the span failed only when `err` is a server-side failure (`errorz` code internal, or
no `errorz` code at all). A 400, 401, 403, 404, 409 or 428 is the API working as designed: the span ends without an
error, otherwise every not-found fills the error view. The request span already marks itself failed on any 5xx.

```go
// End ends span, recording err when it is a server-side failure.
func End(span tracer.Span, err error) {
    if err != nil && isServerError(err) {
        span.SetError(err)
    }
    span.End()
}
```

### Names and attributes

- Names have low cardinality: `<module>.<Operation>` for services, `<service> <METHOD> <route pattern>` for
  clients, `<job>.<step>` for the worker. Never an ID, a query string or a user value in a name: those go in
  attributes.
- Attribute keys are lower dotted: `<module>.<field>` for your own (`note.id`, `outbox.topic`), and the
  OpenTelemetry semantic keys where one exists (`http.request.method`, `http.response.status_code`,
  `db.system`).
- Allowed: resource IDs, `tenant.id`, counts, sizes, enum values (`note.status`), page and size.
- Never: tokens, passwords, secrets, emails, names, request or response bodies, raw SQL with values, full URLs with
  query strings. The rule is the same as for logs: if it may not be logged, it may not be an attribute.
- Set attributes once you know them (`span.SetAttributes(map[string]any{"note.count": len(items)})`), not
  speculatively.

### Outbound calls

Every call to another service goes through an `http.Client` whose transport is go-sdk `tracer.Transport`. It starts
a client span per call (`GET <host>`, with `http.request.method`, `server.address` and `http.response.status_code`),
injects the W3C `traceparent` header so the other service's spans join the same trace, and marks the span failed
on a transport error or a 5xx. Calls to identity use `identityClient(tr)` in `internal/app`, which also sets a
timeout:

```go
client := &http.Client{Timeout: identityTimeout, Transport: tracer.Transport(tr, nil)}
```

For a span name with the route, pass `tracer.WithSpanName(func(*http.Request) string { return "identity GET
/v1/internal/users/{id}" })`; never put the raw path in a name. A cached result (the service token) makes no call,
so it has no client span.

### Worker

The worker has no incoming request, so each run of a job starts a root span and puts its trace ID on the context,
so the job's log lines carry `trace_id` like request logs do:

```go
ctx, span := d.tr.Start(ctx, "outbox.dispatch")
ctx = ctxkit.WithTraceID(ctx, span.SpanContext().TraceID)
defer func() { tracing.End(span, err) }()
```

- One `outbox.send <topic>` producer span per message, child of the dispatch span, with `outbox.id`,
  `outbox.topic` and `outbox.attempts`.
- An empty poll (no rows claimed) still ends its span, but sets `outbox.claimed: 0`; if empty polls flood Tempo,
  sample them out rather than removing the span.
- Linking a send back to the request that enqueued it means storing `traceparent` on the outbox row at `Enqueue`
  time. That needs a migration and is not part of the pattern yet.

### Database

The pgx driver is registered through go-sdk `tracesql.WrapDriver` (`internal/platform/database/driver.go`), so every
statement run under a span becomes a child span with `db.system.name: postgresql` and the statement text. Argument
values are never recorded, so always bind values as arguments (`$1`), never format them into the SQL. `Begin`,
`Commit` and `Rollback` get spans too, which shows where a transaction starts and ends. A statement with no span
above it (health checks, pool maintenance, an idle worker poll) creates no trace.

Repositories still start no spans of their own. Add a `<module>.repo.<Method>` span only for a method whose
statements are worth timing together (a long report).

### Testing

- Tests pass `tracer.NewNoOp()` in `Deps`. Never assert on spans in ordinary handler or service tests.
- `tracing.End`'s error filter gets its own table-driven test (which `errorz` codes mark the span failed).
- For the rare test that must prove a trace crosses a call (the outbound client injecting `traceparent`), build a
  real `tracer.NewOTel` pointed at an unused address and assert on the header, as `service_token_test.go` does.

## Checklist for a new endpoint

- [ ] Permission constant in `module.go`, registered in identity; route behind `RequirePermission`/`RequireAny`.
- [ ] Request DTO with `json` and `validate` tags; response DTO and mapper; no row struct in the response.
- [ ] Handler in the standard order; swag annotations for every param and failure; `make swagger`.
- [ ] Service applies `:any` widening and any state-dependent rule; multi-write steps in `WithTx`; side effects in
      the outbox.
- [ ] Repository method: intent-named, scope from context, `tenant_id` in every `WHERE`, named columns, `RETURNING`,
      version check if editable, 404 on zero rows.
- [ ] Service operations that do more than one call start a `<module>.<Operation>` span and end it with
      `tracing.End`; outbound calls get a client span and `traceparent`; no secrets in attributes.
- [ ] Migration with base columns, `tenant_id`-first index, working `Down`, expand-then-contract safe.
- [ ] Config values in `config.yaml` and `.env.example`, validated in `sections()`.
- [ ] A list a dropdown picks from has an `/options` endpoint; a table with bulk actions has `/bulk-<action>`.
- [ ] Table-driven unit tests; integration tests including scope isolation; mocks regenerated.
- [ ] `make check` passes; `make test-integration` passes when the database changed.
